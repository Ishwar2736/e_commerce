1. Title of the Project

Engineering and Quality Assessment of OmniStore: A Cloud-Native, Responsive Full-Stack E-Commerce Platform Featuring Automated Edge Geolocation, Transactional Mailer Services, and Administrative Verification Workflows

2. Problem Statement

Modern e-commerce ecosystems frequently experience significant operational friction due to disconnected transactional subsystems, poor address validation, unvetted user access, and unresponsive client interfaces. Specifically:

  • Unscreened Customer Registration: Open registration portals allow unverified users and automated bots to flood merchant databases, placing stores at risk of fake orders and payment fraud.
  • Transactional Communication Blackouts: Customers are often left uninformed regarding registration statuses, pending approvals, order invoice breakdowns, and refund credit details.
  • Delivery Inaccuracies from Manual Inputs: Inaccurate manual entry of cities and PIN codes creates high return-to-origin (RTO) costs, whereas automated edge/IP geolocation can reliably auto-detect locations.
  • Cluttered Mobile UX & Rigid Search: Mobile users are burdened by oversized promotional banners that obstruct item search results, while naive search algorithms fail to match singular and plural variants (e.g. failing to match "headphone" to "headphones").

OmniStore provides an end-to-end, object-oriented software engineering solution that unifies edge-based geolocation detection, Google SMTP email delivery, intelligent search routing with automatic banner suppression, and role-based administrative approval gating.

3. Project Objectives

  • Architectural Design & Modularity: Construct a modular, layered full-stack application using Node.js ES Modules, RESTful APIs, and an in-memory/JSON persistent document database.
  • Administrative Verification Gating: Enforce a workflow where newly registered accounts default to pending_approval, requiring explicit administrator review prior to granting login access.
  • Automated Edge Geolocation & Indian PIN Resolution: Automatically detect visitor cities and postal codes via Vercel edge headers (x-vercel-ip-city) and IP lookups, with interactive GPS and India Post API resolution.
  • Real-Time Gmail SMTP Dispatcher: Deliver branded HTML transactional notifications for account registration, administrative approval, itemized order placement, order cancellation, and refund completion.
  • Optimized Search & Mobile Experience: Implement responsive Amazon-style touch-swipe carousels, 2-column mobile grids, and an automated banner-hiding mechanism that smoothly scrolls directly to searched items.
  • Empirical Verification (CO4): Validate correctness, fault tolerance, and security through ten structured test cases.

5. Functional Requirements (FR)

  • FR-1 (Gated Registration & Salted Auth): New customer registrations default to pending_approval with a clear alert: "Registration successful! Waiting for admin approval." Login is blocked with HTTP 403 until approved. Passwords are salted with 16 random bytes and hashed using PBKDF2 (10,000 iterations).
  • FR-2 (Smart Search & Auto-Hide Banners): Searches match across product names, descriptions, categories, and specs with singular/plural support (e.g. "headphone" ↔ "headphones"). Active searches automatically hide hero banners and smoothly scroll directly to matching items.
  • FR-3 (Auto-Detected Delivery Geolocation): Initial page load detects the user's city and postal code via edge headers and IP lookup. The location modal supports GPS auto-detection, 6-digit India Post PIN lookup, and major hub selectors.
  • FR-4 (Cart & Pre-Payment Coupons): Real-time cart drawer with quantity adjustment and coupon pills (WELCOME10, FLAT500, FREESHIP, MEGA50) applied before payment authorization.
  • FR-5 (Multi-Step Checkout & Stock Updates): Collects address info, validates payment, decrements product stock atomically, and computes 18% GST in Indian Rupees (₹).
  • FR-6 (Order Tracking & Returns/Refunds): Milestone shipment timeline with one-click order cancellation (restores stock + issues refund) and return pickups (replacement or full refund).
  • FR-7 (Live Gmail SMTP Notifications): Dispatches HTML receipts for registration, admin approval, order confirmation, cancellation, and refund status using nodemailer.
  • FR-8 (Role-Gated Admin Control Center): Strictly hidden and protected by JWT auth. Enables customer approval/rejection, catalog CRUD, and financial summaries.

8.1 Smart Search & Singular/Plural Stemming (api/index.js)

if (search) {
  const q = search.toLowerCase().trim();
  prods = prods.filter(p => {
    const fullText = `${p.name} ${p.description} ${p.categoryName || ''} ${(p.specs || []).join(' ')}`.toLowerCase();
    if (fullText.includes(q)) return true;

    const terms = q.split(/\s+/).filter(Boolean);
    return terms.every(term => {
      if (fullText.includes(term)) return true;
      if (term.endsWith('s') && term.length > 3 && fullText.includes(term.slice(0, -1))) return true;
      if (fullText.includes(term + 's')) return true;
      if (term === 'headphone' && (fullText.includes('headphone') || fullText.includes('earbud') || fullText.includes('audio'))) return true;
      return false;
    });
  });
}

8.2 Gmail SMTP Email Transport with Timeout Race (api/mailer.js)

export async function sendEmail({ to, subject, html, type, recipientName, metadata = {} }) {
  const emailRecord = { id: `eml_${crypto.randomUUID().slice(0, 8)}`, to, subject, body: html, type, status: 'sent', sentAt: new Date().toISOString() };
  db.addEmail(emailRecord);
  const transporter = getTransporter();

  if (transporter) {
    try {
      const timeoutPromise = new Promise((_, reject) => setTimeout(() => reject(new Error('SMTP timeout (8000ms)')), 8000));
      const sendPromise = transporter.sendMail({ from: `"OmniStore" <${SMTP_USER}>`, to, subject, html });
      const info = await Promise.race([sendPromise, timeoutPromise]);
      emailRecord.deliveryInfo = { service: 'gmail_smtp', messageId: info.messageId, delivered: true };
    } catch (err) {
      emailRecord.deliveryInfo = { service: 'gmail_smtp', error: err.message, delivered: false };
    }
  }
  return emailRecord;
}

8.3 Edge & IP Geolocation Auto-Detection (api/index.js)

if (pathname === '/api/location/detect' && method === 'GET') {
  const vercelCity = req.headers['x-vercel-ip-city'];
  const vercelPostal = req.headers['x-vercel-ip-postal-code'];
  if (vercelCity) {
    return sendJson(res, 200, { success: true, city: decodeURIComponent(vercelCity), pincode: vercelPostal || '', source: 'vercel_edge' });
  }
  // Fallback to IP geolocation lookup with 2.5s timeout
  try {
    const ipRes = await fetch('https://ipwho.is/', { signal: AbortSignal.timeout(2500) });
    const data = await ipRes.json();
    if (data?.city) return sendJson(res, 200, { success: true, city: data.city, pincode: data.postal || '', source: 'ip_lookup' });
  } catch {}
  return sendJson(res, 200, { success: true, city: 'Bengaluru', pincode: '560038', source: 'default' });
}
